# Data Retention

이 대시보드의 데이터는 계속 유지되어야 하므로 저장 키와 데이터 구조 변경을 신중하게 관리합니다.

## 현재 저장 방식

현재 운영 데이터는 브라우저 `localStorage`에 저장됩니다.

| 데이터 | 저장 키 |
| --- | --- |
| YouTube 프로모션 | `yt-studio-promotions-v1` |
| 테마 설정 | `marketing-dashboard-theme-v2` |

이 키는 기존 브라우저에 저장된 데이터를 이어 받기 위해 그대로 유지합니다.

## 변경 원칙

- 저장 키를 바로 바꾸지 않습니다.
- 필드를 삭제하지 않고 먼저 새 필드를 추가합니다.
- 구조 변경이 필요하면 마이그레이션 함수를 만든 뒤 버전을 올립니다.
- CSV export/import는 항상 복구 경로로 유지합니다.
- 샘플 데이터와 실제 데이터가 섞이지 않도록 UI에서 명확히 구분합니다.

## 권장 마이그레이션 흐름

1. 기존 키에서 데이터를 읽습니다.
2. 데이터 버전이나 필드 존재 여부를 확인합니다.
3. 누락된 필드는 기본값으로 채웁니다.
4. 새 구조로 저장합니다.
5. export/import가 같은 구조를 지원하는지 확인합니다.

## 다음 단계 후보

- `src/data/storage.js`로 저장소 접근을 분리합니다.
- `src/data/migrations.js`로 버전별 마이그레이션을 분리합니다.
- 채널별 저장 키를 `src/channels/*` 설정에서 관리합니다.
- 필요 시 IndexedDB로 이전해 대용량 데이터와 파일 기반 캐시를 지원합니다.
